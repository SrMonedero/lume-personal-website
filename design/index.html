Papel + Cian

A small design system so that interfaces built with AI don't look built with AI. No Inter, no purple gradients, no emojis, no cards with rounded-2xl and a shadow. The main piece is DESIGN.md, a rules file that Claude, Cursor and friends read before touching a screen.

01 · Typography

One family, made to be read

Atkinson Hyperlegible Next for everything, and its Mono sibling for data and labels. The Braille Institute designed it so no letter gets mistaken for another: I, l and 1 are distinct; so are O and 0.

Do

  • Only the nine sizes in the scale.
  • Hierarchy with size and color first; weight as support.
  • tabular-nums in tables, prices and counters.

Don't

  • Inter, Roboto or system-ui as a visible font.
  • Light, extrabold or black weights. More than three weights per screen.
  • Gradient text, emojis in headings or buttons, body text under 14px.
02 · Color

Warm neutrals and a single accent

"Papel" (paper) is a gray with an 85° hue, like unbleached paper. "Cian" (cyan, #0099C6) is the only color with intent: the primary action, selection and focus. The rest of the screen is neutral.

Do

  • One bg-accent action per view.
  • Colored text always with accent-text; dark text on the accent.
  • In light mode, the primary button gets a line-strong border.
  • States with a soft background, always with a word or icon too.

Don't

  • Tailwind's default palette (slate, blue, purple…). It doesn't even exist.
  • Gradients of any kind.
  • Loose hex values in components.

Do

  • Multiples of 4 and the semantic tokens above.
  • Less space inside a component than between components.
  • Inner elements never rounder than outer ones.

Don't

  • rounded-2xl, rounded-3xl or rounded-full on cards and buttons.
  • shadow-md and up.
  • Cards inside cards with both border and shadow.

Do

  • Phosphor regular icons, 16px in buttons, inheriting the text color.
  • Buttons with verb + object: "Save booking", not "OK".
  • Messages with real data: "Booking moved to T4".
  • Accent focus ring on everything interactive.

Don't

  • Icons inside colored squares or circles. Emojis as icons.
  • Mixing icon libraries.
  • "Operation completed successfully!" and any exclamation mark.
  • outline-none without an alternative.

## Design

Before creating or changing any interface, read `DESIGN.md` and follow it to the letter.
- Use only the tokens defined in `globals.css` (colors, sizes, spacing, radii).
- Copy the component recipes from `DESIGN.md`; don't invent new styles.
- Icons: Phosphor (`@phosphor-icons/react`). Never Lucide, never emojis.
- If something doesn't fit, stop and propose the change in `DESIGN.md` instead of skipping it.
